# 公开实例、保留测试与负优化

## 可复现入口

```bash
python scripts/benchmark_supply_chain.py fetch --out public-data
python scripts/benchmark_supply_chain.py compare --data public-data --baseline /path/to/3.0 --candidate . --seconds 10 --seeds 17 --out comparison
```

只复核已记录的百题与额外种子解答时，运行 `python scripts/regrade_benchmark.py --data public-data`，无需重新搜索。完整解答、逐题记录与证据边界见 [发布验证说明](../docs/VALIDATION.md)。

清单 `assets/evaluation/public-optimization.json` 固定100个公开优化实例：44个OR-Library容量仓网、56个Solomon百客户时间窗配送。96个原始文件生成100个实例，包含7个明确标注容量的A/B/C实例；容量变体有独立公开参考值，不能说成100个独立业务场景或100种问题。原始数据不随Skill复制，下载时校验原始和规范化文件SHA256，来源变动时停止。

`--subset development|holdout|all` 选择预先划分的12个开发实例、88个保留实例或全部。部分开发题来自历史复测，其余保留题用于本轮代码固定后的检查；公开数据本身可能出现在模型训练中，不能宣称训练意义上的未见题。相同地理位置、容量变体和时间窗变体也存在相关性。

两个版本以交替顺序、单线程独立子进程运行相同输入和预算。`--seeds 17,23,41` 是三次独立搜索，不能把总预算提高后只报告最优值。默认10秒与历史七题的60秒是不同实验，分别报告。共享主机没有物理隔离，不按墙钟时间排快慢。

## 评分与原始证据

- 仓网保留全部非零需求比例、开仓、容量和原始目标成本；使用整客户需求成本乘比例。距公开参考值不超过0.1%为质量达标。
- 配送每户恰好一次，等待允许，检查开始服务窗口与回仓；逐弧使用双精度欧氏距离。严格先比较车数，车数相同时才比较距离；参考车数达到且距最佳已知距离不超过1%为质量达标。公开两位小数参考额外允许0.005的舍入容差。
- 不把最佳已知可行值称为全局最优证书。每次保留完整report.json、进程状态、输入指纹、源码指纹及结果；独立评分不导入被测求解模型。
- 仓网下界的乘子必须在全部原始弧上重算。辅助受限LP/MIP的界不能作为完整问题的保证。报告有效下界、方案成本以及两者差距。

## 负优化判定

同时输出以下项目，禁止用总达标率掩盖单题退步：

1. 原来可行而新版不可行、无完整交付或输出异常。
2. 原来达标而新版不达标。
3. 同车数距离变长、车数增加或仓网成本增加。比较容差取绝对1e-6与相对1e-6的较大者。
4. 原问题有效下界变弱或证书无法独立复算。
5. 新增报告开销、依赖、适用范围收窄及输入兼容性变化。

连续目标差距与达标率一起呈现。按开发/保留、问题类型及随机种子分别汇总胜、平、负、失败数；重复种子不增加唯一题数。一次各类实例的成功不能证明生产就绪，也不能推断全市场最好。

代码修改后需要新的保留集或明确转为开发回归。已看到的保留结果不再用于同一轮调参。`--resume` 仅允许在相同数据、源码与参数指纹下补完中断任务，不能借恢复重跑更好的答案。

## 已有方案的采用复核

```bash
python scripts/supply_chain.py review-optimization --input same-input.json --baseline old/report.json --candidate new/report.json --out adoption-review
```

该入口只对已存在的仓网或配送方案做输入身份、可行性和目标重算，输出择优的`accepted_plan.json`与`review.json`；持平保留旧方案，两者均无效不生成采用方案。它不运行求解器，不能算成额外一次独立答题或用来隐藏裸跑负优化。两个搜索的成本和预算须分别披露；本轮百题原始对照不使用这个复核入口改善分数。

## 3.1本轮实测结果（2026-10-22）

在求解核心固定后，用同一评分器、每实例每版本10秒、种子17、单线程交替比较3.0和3.1原生程序。数值记录见 [optimization-31-summary.json](../assets/evaluation/optimization-31-summary.json)。这不是大模型加载/不加载Skill的因果试验。

| 范围 | 3.0达标 | 3.1达标 | 变化 |
| --- | ---: | ---: | ---: |
| 全部100实例 | 55/100 | 59/100 | +4.00个百分点 |
| 其中88保留实例 | 46/88 | 51/88 | +5.68个百分点 |
| 其中12开发实例 | 9/12 | 8/12 | -8.33个百分点 |
| 44仓网实例 | 39/44 | 39/44 | 持平 |
| 56配送实例 | 16/56 | 20/56 | +7.14个百分点 |
| 六配送实例×三个种子 | 12/18 | 11/18 | -5.56个百分点 |
| 原七题，每题60秒另测 | 7/7 | 7/7 | 持平 |

百题完整方案两版均100/100可行；按实际目标为30改善、56持平、14退步。R101由19车增至20车，从达标变成未达标；不能只报道总达标率上升。三种子复测为预先选定六题的18组成对运行，不增加唯一题数，也未覆盖全部配送题组。固定预算的启发式受停止时点与运行环境影响，不能据此证明每次调用或所有分布都更好。

44题仓网成本全部持平，34题有效下界增强、0题变弱；有效界差中位数18.3596%降至0.0916%，只说明最优性证明更紧。原大规模H1、L1的有效界差仍为36.91%、39.65%，本轮未补齐这项短板。原七题两版都达标，H2/L2配送距离有改善，其他目标持平。

对两份已有结果再做不搜索的采用复核，30题采用新版、70题保留旧版，复核后相对已有方案退步0题。这要使用两个搜索的结果，不能替代原始10秒比较，也不能把复核后的60/100达标冒充新版单次成绩。100项软件检查、60项原有模拟验收另行通过，不计入公开题数。
