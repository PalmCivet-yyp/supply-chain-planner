# 扩展推导与方法审查

将本文件作为方法审查规则使用。`plan_inventory.py`保留1.0基线；2.0的`supply_chain.py`已实现失销/积欠、显式交期情景、有限候选预算分配与政策回测，具体范围见 [引擎说明](v2-engine.md)。其余扩展仍须区分条件推导、已实现与未验证。

## 1. 明确问题是否可识别

- 列出已知、缺失、假设、需求范围、库存状态、决策时点、单位和目标；保留用户给定的口径。
- 只给均值不足以确定安全库存，只给一阶相关不足以确定完整自协方差或牛鞭倍数。可以给参数式或情景范围，不补造分布。
- 对未指定来源的口诀和分类标注框架依赖。遇到多解、重复选项、缺词、因果或主谓颠倒时，不静默改题。分别记录可能的题目意图、业务答案、有效性和置信度；不能唯一作答时允许空答案。
- 不将题库答案作为方法权威。保留与参考答案的分歧、原始评分和仲裁依据；修改同题答案只计回归，不提高封存测试成绩。

## 2. 先核对库存守恒和时间

- 区分实物库存、净库存和库存位置。净库存可以为负；平均实物库存等于平均净库存加平均积欠，不把两者混称。
- 核验库存位置是否已经包含在途、在制和未交客户义务；不得重复加入或扣减。批数、晶圆数和良品件数分别换算，最大产量不等于期望良品产量。
- 使用日历和事件表说明盘点、下单、到货、需求和履约顺序。库存位置补货数量不能替代逐日到货可行性检查。
- 明确积欠与失销：积欠结转到后续日期；失销仅扣到零并单列损失。2.0使用独立实物、欠单、失销状态；1.0不能通过截断最终净库存改装成失销模型。
- 客户宽限可改变到期服务的保护期，但不能据此改写物理交期。保留全部未交需求下的净库存、到期服务状态和实物库存，注明立即交付或统一延迟交付的政策。
- 随机交期和随机良率须检查需求、交期、批内及批间产出的相关性，以及当前批次残余完成时间。仅有均值和标准差不能提供无条件服务保证。

## 3. 区分服务目标、成本目标与预测目标

- CSL是周期不缺货概率；fill rate是及时满足的需求单位比例。另列订单满足率、OTIF、积欠数量和缺货周期数。
- 正态分位数不能直接替代fill rate。周期复核按其期望短缺差求解或注明近似；连续时间、单位Poisson需求、一件一补时，若N为交期未完订单数，fill=P(N<S)=F_N(S-1)。持有加积欠成本的整数分位条件涉及F_N(S)，两者可能差一件。
- 不将成本分位目标等同于已实现服务水平。先求无约束成本最优，再核对服务和可行性约束；明确再订货点的触发前后定义。
- 1.0累计误差缓冲受短样本和重叠起点影响；2.0经验误差混合仍受样本、需求变化和交期假设影响。设计缓冲、近似回退和实际达标率分别披露。
- 以持有、下单、缺货、运输和残值等相关总成本或服务—库存权衡比较政策。没有成本时不补造费率；订单货值不能称为总成本或节省额。
- 不将日MAE、累计需求误差、WAPE、MASE或RMSSE直接当作经济收益。1.0择模按日MAE优先；2.0按保护期总量MAE优先，再通过独立政策回测比较模型成本。

## 4. 核验理论计算的条件

- EOQ适用于稳定已知需求、固定下单费、线性持有费、瞬时到货且无缺货的模型。有限产速p>d时，EPQ=sqrt(2DK/[h(1-d/p)])，大于同参瞬时补货EOQ；不要沿用题干中错误的大小关系。
- 报童先定义Cu与Co，核验利润、进价、残值、额外缺货成本及积欠或失销机制。离散需求取CDF达到临界比例的最小分位；连续需求下的整数成本最优比较相邻可行值。
- 最低服务约束的取整与成本最优取整分开。MOQ、箱规、共享预算、产能、效期或BOM会改变可行域，不能把逐项建议称为整体最优。
- 累计误差方差包含跨期协方差；只有适用独立同分布假设时才用sigma*sqrt(H)。计算随机交期需求须说明独立性与随机和的近似。
- 正态近似若有明显负需求概率，披露限制；不静默改成截零或条件截断分布。两种替代分布也不能混用。
- 运输比较纳入在途、周期、安全库存、货权和服务成本。缺少运价或费率时给阈值；拆分快慢运输须分别列到货事件，不直接套加权交期。
- 比较采购合同时分别计算各方和系统利润、参与条件及协调条件。相邻案例推导不意味着本Skill已经成为供应商分配或MRP工具。

## 5. 设计完整政策回测

1. 按时间划分开发、验证和封存测试区间。基线选择、缓冲校准、参数搜索与需求修复不能使用封存区间的信息。
2. 为所有政策使用共同需求样本、初始库存、未交订单、到货机制、成本、终端库存价值和可行动作。失销销售不是共同的潜在需求；不可识别时使用明确的需求情景或限制结论。
3. 将预测比较与库存政策比较分开；至少保留当前策略作为基线。事后最优只作不可执行的参考下界。
4. 同时报持有与缺货成本、实际CSL、fill rate、平均实物库存、积欠或失销量、MOQ增量以及紧急动作。不在缺失费率时输出总成本改善百分比。
5. 报告SKU、周期与样本量、区间估计和敏感性。重叠滚动窗不视为独立样本；小样本不强行给95%或99%服务保证。
6. 保存输入、参数、版本、哈希、逐日事件、政策动作和异常。修订后用未参与修改的新案例验证，防止只记住训练题。

## 6. 检查交付是否超出实现

- 按“脚本已实现、手工条件推导、尚未验证”逐项标注能力，不用理论题通过率证明代码支持失销、随机交期、预算分配或多级网络。
- 区分题目核对、软件行为测试、业务回测和真实业务收益；只报告实际完成的一层证据。
- 为业务建议给出动作、日期、理由、前提、责任角色和需补信息。未知角色写建议角色，不编造公司流程。
- 使用模拟数据演示时显式标注，不转写为真实经历或已实现的业绩。
