# 数据口径

以下为两版共用源表。2.0配置、中文Excel映射和额外成本字段见 [引擎说明](v2-engine.md)。1.0限制单独标明；2.0新品、稀疏需求及仿真规则以引擎说明为准。

所有 CSV 使用 UTF-8 或 UTF-8 BOM；保留 SKU 前导零。每一行使用同一基本计量单位“件”，脚本不转换箱、套、重量或不同单位。日期统一 `YYYY-MM-DD`，自然日，不跨仓合并。

## items.csv：快照与策略

每个 `sku + location` 仅一行，快照为 `--as-of` 当日结束时。必填字段：

| 字段 | 定义 |
|---|---|
| sku, location | 商品与仓库标识，字符串，不为空 |
| on_hand | 可销售实物库存，包含 reserved，不含残次、冻结、在途 |
| reserved | 已在 on_hand 内分配、待立即交付的数量 |
| backorders | 历史未交且未包含在 reserved 中的欠单 |
| lead_time_days | 今天收盘下新单至到货当天的自然日数，1–365 |
| review_period_days | 每隔多少自然日复核，1–365；与交期之和不超过 366 |
| service_level | 设计周期服务目标，严格在 0.5 与 1 之间，例如 0.95 |
| moq | 最小起订量，非负整数，允许 0 |
| pack_size | 订单数量倍数，正整数 |

可选 `unit_cost` 与 `currency`：要么均为空，要么同时有值；单位成本非负，币种例如 CNY。禁止混币种直接相加。数量字段为非负整数；reserved 不得超过 on_hand。允许 backorders 大于库存，表示存在净欠单。

## demand.csv：连续日需求

| 字段 | 定义 |
|---|---|
| sku, location, date | 唯一复合键，每个 SKU/仓库每天恰好一行 |
| demand_qty | 当天新增客户需求件数，或明确标记为 sales 的实际出库件数 |
| stockout | 可选，0/1，当天是否发生缺货；空值表示未知，不等于 0 |

使用截至快照当天、设定历史窗口的数据。允许保留更早记录，但拒绝快照之后的历史记录。新品不补造上市前的零；1.0要求至少28天并保留阻断诊断，2.0允许至少7天连续尾段的条件情景。主数据没有的 SKU/仓库、重复日行和负需求直接报错，先检查退货、渠道或订单行聚合规则。

`--demand-kind orders` 代表记录新增客户需求，不是订单余额；历史缺货可以不截断记录。`sales` 代表实际出库，不能视为未经约束的需求：缺货标志为 1 或空时阻断该 SKU 的补货数量；即使全部为 0，也将销售代理估计标为条件情景。

缺失日默认阻断相应 SKU。只有用户确认“该日无记录确实等于零需求”，才使用 `--missing-days zero`，并保留这个假设。未来预测代表快照后的新增需求；reserved/backorders 是另外立即扣除的既有义务，禁止把相同订单再次加入未来预测。

## inbound.csv：未交在途

| 字段 | 定义 |
|---|---|
| order_id | 全表唯一的订单行标识，拆分到货必须使用不同标识 |
| sku, location | 与 items 对应 |
| qty | 剩余未交数量，正整数 |
| eta | 预计到货日期 |
| status | confirmed / unconfirmed / cancelled |

必须提供文件。确认没有在途时使用仅含表头的空表。仅计算 `confirmed` 且 ETA 晚于快照的记录；快照日到货应已包含在 on_hand，未到货的需先更新 ETA。仍显示快照日或更早 ETA 的 confirmed 行会阻断该 SKU，避免自动挪期或重复采购。unconfirmed 不纳入可靠供应，并将结果标为条件情景；cancelled 不纳入供应。

## 1.0 输出与通用失败规则

`report.json` 保留参数、输入 SHA-256、状态、预警、预测误差及逐项明细。`planning.csv` 汇总建议，`projection.csv` 给出逐日基线与加入常规补货后的预测净结余。

文件结构错误使命令退出 2，且不创建输出目录。SKU 级缺历史、逾期在途等问题保留在成功生成的报告中；`blocked` 行补货数量为 null。输出目录必须尚不存在，避免覆盖既有结果。导出文本会转义可能被表格软件解释成公式的标识；JSON 保留原标识用于核对。
